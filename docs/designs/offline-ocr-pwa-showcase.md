## Problem Statement
Snap2 already has local OCR models (`public/models/`), host-side OCR (`server.ts`, `server/handwritingRecognizer.ts`), and PWA/push scaffolding (`public/sw.js`, `src/services/push.ts`), but needs a cohesive, 100% offline end-to-end flow for live phone testing and showcasing:
1. Paper lists (e.g., grocery lists) scanned from a phone camera must be processed completely offline on the host, converted into an interactive checklist, and visually mapped back onto the source image.
2. Each OCR run must write clearly named processing stage images to a host folder (`ocr-exports/run-<timestamp>/`) so every preprocessing/recognition step can be inspected and showcased.
3. Random object photos (with no/low readable text) must ask the user *"What is this for?"* and turn their answer + photo into a reminder instead of hallucinating OCR text.
4. Opening the PWA on a phone or desktop must showcase **Today's Reminders** and support random/scheduled reminder nudges.

## What Makes This Cool
- **Two-branch smart capture:** Paper lists become interactive checklists with visual OCR-to-image bounding-box reflection; random object photos turn into a conversational *"What is this for?"* reminder.
- **Transparent in-house AI:** Every scan leaves a cleanly named stage trail (`ocr-exports/run-<timestamp>/`) and highlights where each extracted line came from on the original paper.
- **Zero-cloud, phone-ready PWA:** Live phone camera capture over local Wi-Fi routed to the host PC's offline models, with Today's Reminders greeting the user every time they pull up the app.

## Constraints
- **100% Offline / In-House:** Zero internet calls during OCR or reminder parsing (no Gemini, Groq, or HuggingFace Hub fallbacks when `OFFLINE_ONLY=1` or offline mode is active).
- **Host Processing:** Heavy OCR inference runs on the host machine (`Snap2/server.ts`), while the phone acts as the live camera + PWA client.
- **Mobile Browser Origin Rules:** Phone `getUserMedia` camera access and Service Worker / Web Push require a secure context (local HTTPS cert or `localhost` port-forward).

## Premises
1. Strict Offline Host Lock — All OCR and reminder parsing runs 100% in-house on the host PC (`Snap2/server.ts` + `public/models/`), with zero internet/cloud fallback.
2. Two-Branch Scan + Visual Proof — Text/list photos create a checklist, visually show where the OCR text maps onto the image, and save clearly named stage images per run in `ocr-exports/`. Random object photos prompt *"What is this for?"* to create a reminder.
3. Today's Reminders & Phone Live Test — The PWA works live from a phone's camera over local Wi-Fi (HTTPS/camera-safe origin), surfaces "Today's Reminders" on open, and triggers/schedules reminder nudges.

## Approaches Considered
### Approach A: Minimal Viable Demo Polish
Lock `server.ts` to offline-only OCR, clean up `ocr-exports/` stage naming, add the "What is this for?" prompt, and add a Today's Reminders banner. *Not chosen:* lacks interactive OCR-to-image bounding-box mapping and LAN HTTPS for mobile camera/push.

### Approach B: Full Offline-First PWA + Interactive OCR-to-Image Showcase
Everything in A, plus per-line bounding-box overlays mapping checklist items back onto the scanned photo, `0.0.0.0` LAN binding + local HTTPS dev support for phone camera/PWA/push, and Service Worker / Web Push random-time daily nudges.

### Approach C: Live "X-Ray Filmstrip" Demo Mode + Smart Object Router
Everything in B, plus an in-app side-by-side stage storyboard viewer. *Deferred:* extra UI surface not needed before verifying Approach B live on a phone.

## Recommended Approach
**Approach B — Full Offline-First PWA + Interactive OCR-to-Image Showcase:**
1. **Strict Offline Mode (`server.ts` & `server/handwritingRecognizer.ts`):**
   - Add an explicit offline lock (`OFFLINE_ONLY=1` / UI toggle) so `/api/local-ocr` and `/api/analyze` never call Groq, Gemini, or remote HuggingFace downloads, using only `public/models/`.
2. **Named Stage Folder (`server/handwritingRecognizer.ts` & `server.ts`):**
   - Standardize `ocr-exports/run-<timestamp>-<slug>/` stage filenames (e.g., `01_original.png`, `02_deskewed.png`, `03b_background_flattened.png`, `03c_ruled_lines_removed.png`, `04_contrast_enhanced.png`, `05_adaptive_binary.png`, `06_line_<n>.png`) and expose a read-only `/api/ocr-exports` endpoint for inspection.
3. **Visual OCR-to-Image Mapping & Object Fallback (`src/components/OcrStudio.tsx`, `src/components/UploadModal.tsx`):**
   - Return line bounding boxes from `handwritingRecognizer.ts` and render interactive highlight boxes over the uploaded/captured photo synced with checklist items.
   - When OCR returns empty or low-ink/low-confidence output, prompt *"What is this for?"* and create a reminder from the user's input + photo.
4. **Today's Reminders & Random/Daily Nudges (`src/App.tsx`, `public/sw.js`, `src/services/push.ts`):**
   - Show a prominent **Today's Reminders** card on app launch/focus.
   - Support randomized/scheduled daily Web Push (when subscribed) and in-app reminder nudges on open.
5. **Live Phone Testing (`server.ts`, `vite.config.ts`):**
   - Bind `server.ts` to `0.0.0.0` and support local HTTPS (or `adb reverse` / dev cert) so a phone on the same Wi-Fi can open the PWA, use `CameraCapture.tsx`, and test offline OCR end-to-end.

## Success Criteria
- Turning off Wi-Fi/internet on the host still processes a handwritten grocery list photo end-to-end into a checklist in the app.
- `ocr-exports/run-<timestamp>/` contains clearly named PNGs for every OCR stage of that run.
- Uploading/snapping a random object photo prompts *"What is this for?"* and saves a reminder.
- Opening the PWA on a phone showcases **Today's Reminders** and delivers a reminder notification/nudge.
- `npm run test:unit` and `npm run lint` pass with zero errors.

## Distribution Plan
Local host-run PWA (`npm run dev` / `npm run build` + `npm start`) accessed over LAN/HTTPS from the user's phone browser and installable as a PWA via `public/sw.js`.

## Dependencies
- Local models already present in `public/models/` (`trocr-base-handwritten`, `parseq`, `tessdata`).
- Local HTTPS cert (`mkcert`) or `adb reverse tcp:3000 tcp:3000` for mobile camera/Web Push over LAN.
- VAPID keys in `.env` for Web Push notifications.
