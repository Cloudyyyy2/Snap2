## Problem Statement
Snap2 currently runs its local OCR and image preprocessing in Node/TypeScript (`server/handwritingRecognizer.ts`, `server/printedRecognizer.ts`). To showcase the OCR and image-processing pipeline as a **100% offline, in-house Python OCR engine**—while keeping Snap2's React PWA, phone camera, X-Ray scrubber, Today's Reminders, and Web Push intact—we need a dedicated Python OCR engine under `python_ocr/`.

## What Makes This Cool
- **Real Python CV + ML stack:** Clean, readable Python modules (`python_ocr/preprocess.py`, `python_ocr/recognizer.py`, `python_ocr/server.py`) using OpenCV (`cv2`), NumPy, Pillow, and `onnxruntime` / `transformers` (or `rapidocr-onnxruntime` / `pytesseract`) with local `public/models/` weights.
- **Warm FastAPI sidecar:** Models stay loaded in RAM on `127.0.0.1:8001` (auto-managed by `server.ts`), keeping live phone scans fast (~1-2s).
- **Drop-in contract compatibility:** Emits the exact same `ocr-exports/run-<YYYYMMDD-HHMMSS-mmm>-<profile>/` stage PNGs (`01_original.png` .. `06_line_NN.png`), `normBox` line bounding boxes, `needsUserPurpose` object-photo flag, and `"Python Local OCR"` engine badge in the UI.

## Constraints
- **100% Offline / In-House:** Zero internet calls (`OFFLINE_ONLY=1`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`).
- **Python Environment:** Managed cleanly with `uv` (`.venv` using Python 3.11) in `python_ocr/pyproject.toml` or `requirements.txt`.
- **Zero UI Regression:** Keep `OcrXRayViewer`, interactive bounding-box highlights, `"What is this for?"` object prompt, Today's Reminders, and Web Push working seamlessly.

## Approaches Considered
### Approach A: Persistent Python FastAPI Sidecar (`python_ocr/`) *(Selected)*
`server.ts` auto-starts/health-checks `python_ocr/server.py` on `127.0.0.1:8001` and routes `/api/local-ocr` (and `/api/extract-reminder` local path) to it.
### Approach B: On-Demand Python Subprocess CLI
Spawns Python per scan. *Not chosen:* reloads ONNX/TrOCR weights on every scan (slow for live phone demos).
### Approach C: Full Python Backend Rewrite
Replaces `server.ts` completely. *Not chosen:* throws away working Web Push, reminder sync, and Vite dev integration.

## Recommended Approach (`python_ocr/` Architecture)
1. **`python_ocr/preprocess.py` (OpenCV Image Processing):**
   - Decode base64/bytes -> EXIF upright -> grayscale -> dark-mode auto-inversion -> deskew/perspective cleanup -> illumination flattening -> ruled-line removal -> contrast enhancement -> adaptive binary + line segmentation (`normBox` coordinates).
   - Writes `01_original.png`, `02_deskewed.png`, `03b_background_flattened.png`, `03c_ruled_lines_removed.png`, `04_contrast_enhanced.png`, `05_adaptive_binary.png`, `06_line_NN.png`, and `extracted_text.txt` to `ocr-exports/run-.../`.
2. **`python_ocr/recognizer.py` (Offline Python OCR):**
   - Loads local `public/models/trocr-base-handwritten` (via `onnxruntime` / `transformers` with `local_files_only=True`) and/or `rapidocr-onnxruntime` / `tesseract` for printed/handwriting, returning `{ text, lines: [{ text, confidence, bbox, normBox }], recognizer: 'python-local-ocr', needsUserPurpose, exportDirName }`.
3. **`python_ocr/server.py` (FastAPI + Uvicorn):**
   - `GET /health` -> model readiness + `offlineOnly: true`.
   - `POST /ocr` -> runs `preprocess.py` + `recognizer.py` and returns the JSON payload.
4. **Node Bridge (`server.ts`):**
   - On startup (when `PYTHON_OCR_ENABLED !== '0'`), auto-spawns `.venv/Scripts/python.exe -m uvicorn python_ocr.server:app --host 127.0.0.1 --port 8001` (or connects if already running) and routes `POST /api/local-ocr` to `http://127.0.0.1:8001/ocr`, then runs `correctTextWithLexicon` + `parseReminderLocally`.

## Success Criteria
- `python_ocr/` runs standalone (`pytest` / direct CLI/API test) and completely offline.
- Scanning a handwritten grocery list from the phone routes through `python_ocr/`, writes named stage PNGs to `ocr-exports/`, and renders bounding-box highlights + X-Ray scrubber in the PWA.
- Scanning a blank/object photo returns `needsUserPurpose: true`.
- `npm run lint` and `npm run test:unit` remain green.
